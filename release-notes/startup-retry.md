feat: add `runner.startup_retry` so the daemon retries the initial connection to the Forgejo instance instead of exiting when it is unreachable at startup. This is useful when the runner and the instance are started together (for example in docker compose) or when the instance is temporarily down, as it avoids having to manually restart the runner. It is disabled by default to preserve the previous fail-fast behaviour; when enabled, the connection is retried with exponential backoff (`max_retries`, `initial_delay`, `max_delay`), with `max_retries: 0` retrying indefinitely.
